## Design Context

### Users
The app serves people who encounter Markdown on iOS, not only people who write
Markdown. They receive `.md` files from chat apps, AirDrop, Files, email,
AI tools, developer workflows, Obsidian exports, project READMEs, meeting
notes, product docs, and study materials. Their job is to open the content
immediately, read it comfortably, then turn it into a format other people can
understand without installing the app or knowing Markdown.

### Brand Personality
The product should feel refined, editorial, and capable. It should make a raw
Markdown file feel like a finished article, report, manual, book, or shareable
artifact. The emotional goal is quiet confidence: the app should feel native
and obvious on iOS, while making content feel more valuable the moment it opens.

### Aesthetic Direction
The visual direction is premium reading and presentation, not a developer
editor. Avoid generic Markdown previewer chrome, plain GitHub clones, terminal
aesthetics, busy file-manager layouts, and decorative AI gradients. The default
surface should feel like a calm editorial reader with strong typography,
clear hierarchy, soft paper-like backgrounds, purposeful controls, visible
reading progress, and one-tap delivery actions. Reading modes should be treated
as content identities: Article, Manual, Book, Report, and Cards rather than
simple color themes.

### Design Principles
- One second from file to finished-looking work: opening a Markdown document
  should immediately produce a polished reading surface, not a raw preview.
- Reader first, presenter second, editor later: prioritize opening, reading,
  navigation, and share-ready output over text editing controls.
- Content shape over skin: modes should change the perceived identity of the
  content, not merely swap colors.
- Mobile Markdown needs craft: Chinese typography, mixed-language rhythm,
  code blocks, tables, images, and long-document navigation must be treated as
  core design details.
- System-native, not generic: use iOS conventions where they reduce friction,
  but make the reading surface distinctive enough to feel like a dedicated
  Markdown presentation tool.
