# 思库（SiKu）—— AI Native 个人第二大脑 · 设计文档

- 日期：2026-07-07
- 状态：设计定稿，待实现规划
- 工作代号：思库（SiKu，取"思考 + 知识库"，最终产品名发布前另行确定）
- 关系说明：独立新产品，**不在 MarkGo 内实现**，实现时新建独立仓库。本文档暂存于 MarkGo 仓库的 specs 目录，因为设计讨论发生在此。

---

## 1. 产品定义

**一句话**：把你收藏的知识，变成你自己的思考。

**核心理念**：AI 不替用户思考，而是刺激、辅助用户思考并使其成长。知识库负责"记住"，Agent 群体负责"碰撞"，结论永远由用户产出。

**产品边界（防泛化）**：

它是：
- 一个什么都能扔的个人知识库（零整理成本，Agent 自动组织）
- 一个用你自己的知识做弹药、由 Agent 互相辩论来刺激你思考的"思考室"

它不是：
- 笔记编辑器（不做富文本编辑）
- 通用 AI 聊天（不回答与用户知识库无关的闲问）
- 代写工具（Agent 永远不替用户产出观点；无用户判决则无终稿）

**目标用户**：第一版只服务作者本人（重度 AI 用户，训练产品/商业思维，沉淀阅读，产出 PRD 与决策）。用爽之后再考虑泛化。

## 2. 三大用户动词

产品只有三个一级空间，对应三个动词：

| 动词 | 空间 | 体验目标 |
| --- | --- | --- |
| 扔 | 收集箱 | 粘贴/拖文件/存 URL，一个动作，不问任何问题；Agent 后台自动消化 |
| 找 | 图书馆 | 自然语言提问，得到带引用的综合回答（非文件列表）；wiki 可浏览 |
| 想 | 思考室 | 抛出议题，Agent 辩论团用库内知识互相交锋，用户当裁判下判决，产出带用户观点的成品 |

## 3. 总体架构

四层，自下而上：

```
┌──────────────────────────────────────────────────┐
│  Web 前端（自建，Vite + TypeScript）                │
│  三空间：收集箱 / 图书馆 / 思考室                     │
│  视觉由 frontend-design（Claude Design）出方案       │
├──────────────────────────────────────────────────┤
│  后端服务（Node/TypeScript + Claude Agent SDK）      │
│  REST API + 摄入任务队列 + Agent 会话编排 + 简单密码认证 │
├──────────────────────────────────────────────────┤
│  知识引擎（claude-obsidian skills 二开，MIT）        │
│  摄入 / 混合检索 / 带引用问答 / 巡检 + 自研思考室 skill 群 │
├──────────────────────────────────────────────────┤
│  Vault（纯 Markdown + OKF 约定 frontmatter）        │
│  Git 版本化；标准 Obsidian 库，可直接用 Obsidian 打开  │
└──────────────────────────────────────────────────┘
```

**部署**：NeoSpark 服务器（复用 cc-connect 的 Docker 部署模式），简单密码登录，手机浏览器可用。

**LLM 接入**：Anthropic API（现有 key 管道）。成本分层：后勤梯队用 Haiku 级模型，辩论团/教练用大模型。

## 4. 数据层（Vault）

- 目录沿用 claude-obsidian 约定：`wiki/sources/`、`wiki/entities/`、`wiki/concepts/`、`wiki/sessions/`、`wiki/index.md`、`wiki/log.md`；原始文件进 `.raw/`（不可变）
- **新增 `wiki/thinking/`**：思考室产出（判决书、分歧地图），`type: thinking-artifact`，frontmatter 记录本次思考引用的库内页面
- frontmatter 按 **Google OKF 规范**（Apache 2.0，2026-06 发布）补齐：`type`（必填）、`title`、`description`、`tags`、`timestamp`、`resource`——换取与任何 Agent 生态的互操作性，成本近零
- 页面互链用 `[[wikilink]]`
- 整个 vault 用 git 管理，Agent 每次写入自动 commit：可回滚、可追溯

## 5. 知识引擎与 Agent 阵容

### 5.1 底座选型（已决策）

以 **claude-obsidian**（AgriciDaniel，MIT，8.6k star）为知识引擎二开，理由：

- 摄入（实体/概念提取、并行子 Agent、文件锁多写保护）、混合检索（BM25 + 余弦重排）、带引用问答、健康巡检、验证员预提交审计全部现成，且有约 1240 断言的测试
- 原生就是多 Agent 架构，与"Agent 群体"愿景同构
- 依赖 Claude Code / Agent SDK 运行，与现有服务器上的 cc-connect 部署经验完全吻合
- vault 纯 Markdown、Obsidian 兼容、与 OKF 天然接近

被否掉的候选：lucasastorian/llmwiki（Web 壳现成但引擎弱、无 release，且通用文档库 UI 帮不上灵魂功能）；nashsu/llm_wiki（GPLv3 + Tauri 桌面，与 Web 方向冲突，可借鉴其两步思维链摄入等设计思想）；nvk/llm-wiki（CLI 指令协议，无可复用服务）。

### 5.2 后勤梯队（claude-obsidian 现成能力二开 + 汉化，用户基本无感）

| Agent | 职责 | 触发 |
| --- | --- | --- |
| 摄入员（并行子 Agent） | 新内容 → 提取实体/概念 → 建关联 → 归档 | 扔进内容时自动 |
| 检索答疑员 | 混合检索 → 读全文 → 带引用回答；答案可一键存为新页面 | 图书馆提问时 |
| 图书管理员 | 巡检：孤页、死链、矛盾声明、知识缺口 | 定时夜巡 |
| 验证员 | Agent 写入 vault 前的质量审计 | 每次写入前 |

### 5.3 思考室梯队（自研，产品灵魂）

核心原则：**Agent 之间思维碰撞，用户是观众、插话者、最终裁判**——不是多 Agent 轮流盘问用户。

| Agent | 职责 | 铁律 |
| --- | --- | --- |
| 辩论团（3-4 个，立场按议题动态生成） | 立场互斥，互相交锋；每个立场必须锚定库内真实页面 | 禁止编造库外观点；引用必须带出处 |
| 教练（裁判长） | 不参与辩论；控节奏（叫停/延长）、在判决幕把问题踢回用户，追问"用你自己的话说理由" | 永远不给答案、不下结论 |
| 记录员 | 产出分歧地图 + 用户判决书 | 判决书结论只来自用户亲口所述 |

思考室 skill 群与 claude-obsidian 的 15 个 skill 同机制实现（同一 vault 上的新 skill），不是异物。

## 6. 思考室：三幕制交互（核心体验）

设计依据：Karpathy llm-council 的三段式（并行独立作答 → 匿名互评 → 主席综合）+ 多 Agent 辩论（MAD）研究的经验教训。

**流程**：

1. **开题**：用户抛出议题，系统按复杂度建议轻/重分级，用户可覆盖
2. **第一幕 · 立论**：辩论团并行、互相隔离地基于库内素材各自立论；界面为并排卡片（每张：立场 + 引用页面）。**轻议题到此为止**，用户直接下判决
3. **第二幕 · 交锋**（重议题）：Agent 看到彼此立论，捉对反驳；**默认 2 轮封顶**（教练可延长）；**前两轮禁止让步认输**（防假共识）；用户随时插话（发言被 Agent 认真对待和反驳）、点将（"丙怎么看甲这条？"）、喊停某条战线
4. **第三幕 · 判决**：各方一句话终陈 → 教练把问题踢给用户："你的判决是什么？用你自己的话说理由。" 只说"我同意甲"过不了关
5. **收束**：记录员产出**分歧地图**（各方论点、交锋点、引用页面）+ **用户判决书**（只含用户观点）
6. **沉淀**：两者存入 `wiki/thinking/` 并自动摄入。下次相关议题，**用户上次的判决作为一方立场登场**——过去的自己参与辩论，被现在的自己推翻或加固，思考复利滚动

**MAD 研究教训的落地**：

| 研究结论 | 本设计的应对 |
| --- | --- |
| 思维退化（DoT）：单 Agent 自我反思无效，需真对手 | 碰撞场方向本身的依据 |
| 假共识：Agent 倾向过早趋同，多数派压力放大错误 | 结构性免疫——从不要求 Agent 达成共识，产出是分歧地图，结论只归用户 |
| 交锋烈度需适中 + 自适应叫停 | 2 轮封顶 + 前两轮禁止让步 + 教练控场 |
| 轮数即成本，简单议题不值得辩 | 轻/重议题分级 |

**会话可中断续聊**，状态存 vault。

## 7. Web 界面

- **收集箱（默认首页）**：大输入区（粘贴/拖文件/URL），一个"扔进去"动作；下方摄入流水实时展示 Agent 消化过程（提了哪些概念、连上哪些旧知识）——"Agent 在为你工作"的第一可见现场；手机端优先保证此页体验
- **图书馆**：顶部提问框（带引用回答，可一键存为新页面）；wiki 按 `type` 分区浏览，`[[链接]]` 可点；侧栏展示图书管理员巡检报告，**知识缺口可一键"就此开一场思考"**（通向思考室的暗门）
- **思考室**：三幕制布局——立论幕（并排卡片）、交锋幕（中央辩论流 + 底部悬浮插话框）、判决幕（左分歧地图、右判决书，用户口述、记录员整理、用户确认）
- 视觉气质：**书房里的圆桌**，不做赛博聊天室；实现阶段用 frontend-design（Claude Design）出具体方案

## 8. MVP 分期与验收

| 期 | 内容 | 验收标准 |
| --- | --- | --- |
| **M1 地基** | 服务器部署 claude-obsidian + Agent SDK 无头驱动；收集箱 + 图书馆；扔 → 自动摄入 → 带引用问答闭环 | 扔进 50+ 篇真实存货，问 10 个真问题，答案质量作者本人认可 |
| **M2 灵魂** | 思考室三幕制全流程（组队/立论/交锋/判决/沉淀）；`thinking/` 沉淀与再登场 | 用它想清楚 1 个真实产品决策，且判决书观点确属用户本人 |
| **M3 复利** | 图书管理员夜巡 + 知识缺口开题暗门；思维体检卡（每次会话记录用户在哪类追问上最虚，长期形成成长曲线）；手机端打磨 | 连续使用 2 周不觉得是负担 |

**M1 的第一个任务是验证性 spike**：claude-obsidian 在服务器上无头跑通、真实摄入质量过关。不过关的退路：按其思路自建摄入层，数据格式（vault/OKF）不变，上层设计不受影响。

## 9. 风险清单

1. **摄入质量是生死线**：垃圾摄入 → 辩论团捞不出好料 → 辩论空洞。M1 验收必须苛刻，spike 前置
2. **辩论精彩但空洞**：缓解——立场必须锚定库内真实页面、禁止编造库外观点，写进 skill 铁律，由验证员审计
3. **Token 成本**：轻/重分级、2 轮封顶、后勤用 Haiku、只有辩论团/教练用大模型
4. **单用户产品惰性**：夜巡报告 + 体检卡制造回访钩子；本质成败取决于是否真的让用户想得更清楚——这正是"先服务自己"的意义

## 10. 关键决策记录

| 决策 | 结论 | 备选与否决理由 |
| --- | --- | --- |
| 产品核心 | 思考陪练为魂、产出成品为形（A+C） | 纯陪练太窄；纯问答同质化且违背"不代笔"初心 |
| 载体 | 独立新产品，Web 端 | 塞进 MarkGo 会把两个产品心智都做糊 |
| Agent 交互范式 | Agent 互相辩论、用户裁判 | 多 Agent 轮流追问用户——被用户明确否决 |
| 知识层范式 | LLM Wiki（知识编译）而非传统 RAG | RAG 每次从零检索，知识不复利 |
| 底座 | claude-obsidian 二开 | 见 5.1 |
| 数据格式 | OKF 约定 frontmatter | 互操作性收益大、成本近零 |
| 部署 | 自有服务器 Docker + 密码登录 | 本机跑丢失移动捕获；云 SaaS 与单用户阶段不匹配 |
